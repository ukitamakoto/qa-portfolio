# Video-meeting SaaS (staging QA engagement)

A QA engagement on the staging environment of a browser-based video-meeting product. The product covers scheduled meetings and SFU calls (camera, microphone, screen share, recording, transcription), a workspace (channels, chat, files, tasks), support tickets and an admin area.

**Test tooling:** Playwright (multi-context) · WebRTC with fake media · REST and WebSocket inspection · Google Sheets/Drive API for evidence publishing

## What I did

- Wrote and ran 55 test cases, most of them automated with Playwright using two real accounts at the same time.
- Replaced the camera, microphone and screen with an animated canvas stream, so that two automated participants could join a real call and see each other.
- Logged every case with evidence (screenshots, side-by-side call videos, API responses) and published the cases and the evidence to a shared tracker automatically.
- Ran a security pass covering the authentication lifecycle, access control (IDOR), stored XSS, upload validation, security headers and brute-force protection.

The reusable part of this work is public, with nothing from the client: **[qa-video-meeting-toolkit](https://github.com/ukitamakoto/qa-video-meeting-toolkit)**.

## Results

28 passed · 18 failed · 9 still to confirm. Three failed security cases appear below without their steps; the details were reported privately.

## Findings, by category

- **Real-time propagation:** a live update persisted on reload but did not render for the other user until they reloaded. *(High)*
- **File upload:** executable and markup files were accepted, and non-images were served inline. Private storage bounded the impact. *(High)*
- **Authentication lifecycle:** a session stayed valid after logout. *(High)*
- **Security headers:** the app sent none, and the API sent only some. *(Medium)*
- **Missing affordance:** one entity could be created and edited but never deleted. *(Medium)*
- **Layout:** in one share layout the sidebar thumbnails lost their aspect ratio, and one mobile view overflowed. *(Medium/Low)*

Much was also solid: input was escaped in the places checked, other users' records could not be read, search was scoped to the caller's groups, and anonymous guests were correctly gated.
